## 2. 決裁者体験のゴールと基本原則

### 2.1 決裁者が体験後に言えること

> 「規程に聞くと結論と次の手続きが出て、根拠の条文まで辿れる。ないことは担当者確認になる。」

### 2.2 実行ルール（実装時の鉄則）

1. **1 Phase ずつ実装し、受け入れを満たしてから次へ進む**（一気に作り変えない）。
2. **デフォルト画面に技術用語・デモ操作盤・早期のROIを出さない**（社員が社内規程に聞く本物のチャットにする）。
3. **カスタマーサポートの「店舗サイト背景＋右チャット」は流用しない**。社員向けチャットアプリ（ヘッダー＋スレッド＋入力欄）の型を維持する。
4. **Core接続（Sample / BYOK / Trial）とナレッジパック構造は維持する**。Access Mode やマイナレッジ投入は設定・情報シート内へ収容し、初期視野をすっきり保つ。
5. **掲載課題「最初のガイド質問の空振り」を解消する**。1手目で「該当なし」に落とさず、代表的な成功パス（半休＋在宅の併用可否）へ1タップで導く。

### 2.3 PC / スマホ（SP）の画面型

```text
【スマホ表示（商談の主戦場）】実機・片手操作
  ┌───────────────────────────┐
  │ 社内ナレッジAI     (i) [⚙] │
  ├───────────────────────────┤
  │ [Bot] 何でも聞いてください │
  │ [用件チップ（代表質問）]    │
  │                           │
  │ [スレッド（結論カード）]   │
  │                           │
  │ [メッセージ入力欄]    [↑] │
  └───────────────────────────┘

【PC表示】デスクトップ閲覧
  ┌──────────────────────────────────────────────────────────┐
  │ 社内ナレッジAI                                    (i) [⚙] │
  ├──────────────────────────────────────────────────────────┤
  │ [スレッド（幅広中央コンテナ / 結論ファースト）]           │
  │                                                          │
  │ [用件チップ / 結論カード / 次のアクション]                 │
  │                                                          │
  │ [メッセージ入力欄]                                   [↑] │
  └──────────────────────────────────────────────────────────┘
```

- **SP（主戦場）:** 1台のスマホで代表質問から結論・根拠・次の手続きまで片手で完走できる。
- **PC:** 同一チャットアプリのレスポンシブ幅広表示（店舗埋め込みや右チャット型にはしない）。

### Phase UX-1 — Experience のダイエット
- **目的:** 最初の画面を「社員が社内規程に聞くチャット」に寄せ、デモ操作盤・注記・早期のROIを薄くする。
- **対象ファイル:**
  - `src/components/InternalKnowledgeDemo.tsx`
  - `src/components/conversation/ConversationShell.tsx`
  - `src/components/conversation/IntentQuickReplies.tsx`
  - `src/styles/scaffold.css`
- **やること:**
  1. ヘッダー・バッジの整理:
     - 「サンプル」等のデモ用バッジの主張を抑え、ボトムシートの見出しも自然な日本語に整理。
  2. ウェルカムメッセージと空状態の簡素化:
     - 3行あった説明文を1文のシンプルな案内へ短縮。
     - 初期表示時に不要な「リセット」リンクを非表示化（質問送信後のみ表示）。
  3. 技術語・早期ROIの非表示化:
     - スレッド末尾の常時 `RoiPaybackCta` をスレッド内から撤去（UX-4へ移設）。
     - 回答下の「回答ソース: 実AI（Structured Output）/ サンプル固定回答」等のデモ用注記を非表示化。
- **受け入れ条件:**
  - [ ] 起動直後のスレッド内に、ROIシミュレータへのリンクが露出していない。
  - [ ] ウェルカム文が1文以下で、すぐに用件チップを押せる状態になっている。
  - [ ] 回答下に fixture や LLM といった内部技術用語が表示されない。
  - [ ] 設定アイコンから Access Mode は正常に開ける。
- **やらないこと:** Access Mode やナレッジ投入機能の削除。

---

### Phase UX-2 — 代表3手の固定
- **目的:** 商談で決裁者に価値が伝わる「代表3手」を、迷わずワンタップで進行できるようにする。
- **対象ファイル:**
  - `src/components/conversation/IntentQuickReplies.tsx`
  - `src/components/conversation/ConversationShell.tsx`
  - `src/mocks/guided-questions.ts`
  - `data/sample/towa-corporate-rules-v1/intent-tree.json`
- **代表3手の定義:**
  1. **第1手:** 起動直後の用件チップから「午前半休のあと午後在宅できる？」（半休＋在宅の併用）を1タップで送信
  2. **第2手:** 結論カード（「条件付き」バッジ＋結論1文＋要点＋手続き）を確認
  3. **第3手:** 「根拠を見る」を開き、該当規程（勤怠細則・在宅規程）の該当条文抜粋を確認
- **やること:**
  1. 起動直後のチップの先頭に、成功パスである代表質問（「午前半休のあと午後在宅できる？」）を配置し、1タップで質問・回答へ到達できるようにする。
  2. 該当なし（コアタイム）を先頭に置かず、代表3手の後に配置する。
- **受け入れ条件:**
  - [ ] 起動直後の最初のチップを押すだけで、ローディングを経て即座に結論カードが表示される。
  - [ ] 1手目で「該当なし」にならず、複数規程にまたがる実践的な回答が得られる。
  - [ ] 回答後のチップから「根拠を見る」を押すと、該当条文の抜粋が展開される。
- **やらないこと:** 自由文入力の廃止、Intentドリルダウンの全廃（代表質問をショートカットとして先頭に配置）。

---

### Phase UX-3 — 結果の読みやすさ（結論ファースト）
- **目的:** 回答直後に**「結論（ステータス＋要点）」**が画面上部にフィットし、スクロールで読み始めが隠れないようにする。
- **対象ファイル:**
  - `src/components/conversation/ConversationShell.tsx`
  - `src/components/conversation/DecisionCard.tsx`
  - `src/styles/scaffold.css`
- **やること:**
  1. 回答生成完了時の自動スクロールを、最下部への機械的ジャンプ（`threadEndRef.scrollIntoView`）から、最新回答カードの先頭が画面上部にフィットするスクロールへ改善。
  2. 回答カードの先頭にある「結論ステータス（可能／条件付き／要確認）」と結論文がファーストビューで即座に読めるようにする。
- **受け入れ条件:**
  - [ ] 質問送信後、回答が表示された瞬間に結論（ステータスバッジと結論1文）が画面上部に見える。
  - [ ] 回答末尾の次アクションやバナーに画面が飛ばされず、上から順に自然に読める。
  - [ ] 根拠を展開した際も画面が乱れず、該当規程の条文と理由が確認できる。
- **やらないこと:** Decision Card の構造（Answer Skeleton）の破壊。

### Phase UX-4 — Adoption の後段配置
- **目的:** 投資回収（ROIシミュレータ）や詳細設定（Access Mode / マイナレッジ）を、体験の邪魔をしない「商談の後半」に配置する。
- **対象ファイル:**
  - `src/components/InternalKnowledgeDemo.tsx`
  - `src/components/conversation/ConversationShell.tsx`
  - `src/components/RoiPaybackCta.tsx`
- **やること:**
  1. 回答のたびにスレッド末尾に出ていた `RoiPaybackCta` をスレッドから撤去。
  2. 代表3手（根拠確認まで）を完走したタイミング、および設定シート末尾（`settings`）にのみ配置する。
  3. `VITE_ROI_SIMULATOR_URL` 連携の仕様（`kit=chatbot`、`industry=other`、`cat=internal`、別タブ、`no-print`）を維持する。
- **受け入れ条件:**
  - [ ] 前半（質問〜結論〜根拠確認）の最中に ROI が視界に入らない。
  - [ ] 代表3手完了後、またはヘッダーの設定アイコンを開いたときに、自然な形で「投資回収の目安を見る」が開ける。
  - [ ] 環境変数が未設定の場合はボタンが非表示になる。
- **やらないこと:** 試算ロジックのデモ内複製、iframe 埋め込み。

## 4. やらないこと（スコープ外の明記）

本改修では、以下のことは行わない。

- **店舗サイト＋右チャットレイアウトへの改装:** 社内業務ツールであるため、カスタマーサポートの店舗型は適用しない。
- **Intent Tree の大幅増殖、新業種パックの追加:** サンプルパック（東和産業規程集）の代表性を高めることに集中する。
- **Core の再実装:** `@axeon/ai-demo-core` 接続を維持する。
- **本番の社内認証・人事労務システム連携:** デモの範囲外。
- **Access Mode / Trial の削除:** 初期視野から外すだけで、設定内から利用可能に維持する。
- **UX-0 より前のコード改修、途中フェーズでの `ideal_pf` 先行更新:** 画面が固まってから同期する。
